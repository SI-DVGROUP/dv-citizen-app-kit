# Documentation

- [MUST] Maintenir la spécification liée au changement et la documentation utilisateur ou d'exploitation affectée.
- [MUST] Décrire les usages et décisions métier dans un langage compréhensible par le Citizen Developer.
- [MUST] Distinguer les faits vérifiés, les décisions, les questions ouvertes et les éléments à valider.
- [MUST] Ne pas documenter comme disponible une commande, intégration ou capacité non présente et vérifiée.
- [SHOULD] Conserver les décisions durables dans les specs terminées ou la documentation de référence plutôt que dans une conversation temporaire.
