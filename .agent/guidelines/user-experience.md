# Expérience utilisateur

- [MUST] Concevoir les comportements selon les besoins et termes métier validés, sans inventer de règle.
- [MUST] Présenter les erreurs et confirmations dans un langage simple et actionnable, sans détails techniques sensibles.
- [MUST] Ne pas considérer une interface masquée comme une protection d'accès ; appliquer les autorisations côté confiance.
- [SHOULD] Réutiliser le design system et les composants accessibles déjà approuvés par le projet.
- [SHOULD] Prévoir les états de chargement, absence de données, erreur et succès lorsque le parcours le nécessite.
- [MUST] Faire valider les parcours fonctionnels par le Citizen avant de clore la demande.

Aucun design system ni cadre d'accessibilité technique n'a été détecté ; les choix spécifiques sont **À valider par l'IT**.
